# GitHub Actions: моніторинг Telegram NFT Gifts

Цей набір файлів додається **поверх Fork** `ackermaness/gifttracking` (НЕ замість усіх файлів репозиторію). Працює незалежно від старого нескінченного `GiftMonitor` і **не відправляє особистих повідомлень власникам NFT**: єдиний вихід — повідомлення твоєму `NOTIFY_CHAT_ID` через Bot API. Публічний `@username` власника, якщо доступний, з'являється в сповіщенні з кнопкою переходу.

## Що робити

1. Скопіюй файли з цього пакета у відповідні шляхи репозиторію, зберігши решту оригінальних файлів.
2. Створи бота через `@BotFather` і натисни **Start** у діалозі з ним.
3. Отримай `TG_API_ID` і `TG_API_HASH` через `my.telegram.org/apps`.
4. **Локально** на своєму комп'ютері встанови Python 3.11+, завантаж Fork, у каталозі проєкту виконай `python -m pip install -e .`, а потім `python tools/create_actions_session.py`. Авторизацію введи лише у власному локальному терміналі. Скрипт виведе **секретний** рядок `TG_SESSION_STRING` — скопіюй одразу в GitHub Secrets; **не надсилай нікому, навіть в цей чат**.
5. В GitHub відкрий репозиторій → **Settings → Secrets and variables → Actions → New repository secret**. Створи рівно п'ять секретів: `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_STRING`, `BOT_TOKEN`, `NOTIFY_CHAT_ID` (числовий ID твого діалогу з ботом). Не додавай ці значення в публічні файли.
6. Перейди до **Actions → Monitor Telegram gifts → Run workflow**. Перший запуск має надіслати привітання й запам'ятати поточні лічильники; про старі подарунки він не повідомляє.
7. Далі планувальник намагатиметься запускати перевірку кожні 5 хвилин. Перевіряй вкладку Actions на помилки й попередження.

## Як працює скрипт

- Через MTProto отримує каталог `payments.getStarGifts`.
- Для колекцій, у яких доступний унікальний подарунок `-1`, читає `availability_issued`.
- Порівнює з лічильником SQLite попередніх запусків.
- При збільшенні запитує кожний новий `slug-номер` через `payments.getUniqueStarGift` й відправляє тобі інформацію про доступного власника.
- Між запусками зберігає SQLite у GitHub Actions cache. Кожне виконання створює новий cache key, а наступне відновлює найновіший відповідний.
- Коли колекцій багато, в межах 210 секунд перевіряє максимум можливих, а наступного разу продовжує з наступного місця. Нові колекції в каталозі перевіряє порціями по 20 за запуск.

## Обмеження та безпека

- GitHub Actions **не є гарантованим 24/7-сервером**: запуски можуть затримуватися чи пропускатися, тому сповіщення не гарантовано прийде за рівно 5 хвилин.
- Cache **може бути очищений або витіснений**. Якщо база загубиться, перший запуск знову виставить базові лічильники, і деякі подарунки можуть бути пропущені. Для критично важливого моніторингу потрібне надійніше сховище.
- У публічному репозиторії Actions-логи й залежно від налаштувань кеші можуть бути доступні іншим людям; тому секрет MTProto живе **тільки у GitHub Secrets**, а не в кеші чи коді.
- `TG_SESSION_STRING` фактично надає доступ до Telegram-акаунта; будь уважним до безпеки GitHub-акаунта та сторонніх змін workflow. Можна використовувати окремий Telegram-акаунт для моніторингу.
- Оригінальні файли з функціями автоповідомлень **залишаються в старій кодовій базі**, але новий Actions-процес їх не викликає. Для нашого бота використовуй тільки `actions_monitor.py`.
- Для публічних репозиторіїв GitHub може автоматично вимкнути schedule після 60 днів без активності.
- Не запускай старий `python -m gift_tracking` із конфігураціями, які вмикають auto-DM. Новий Actions-сценарій цього не робить.
